# 프로젝트 개발 규칙 (Project Development Rules)

## 1. 모바일 브라우저 호환성 유지 (Mobile Browser Compatibility)
- 코드를 추가하거나 수정할 때는 항상 **안드로이드(Chrome, Samsung Internet 등)** 및 **아이폰(iOS Safari 등)** 모바일 브라우저 호환성을 염두에 두어야 합니다.
- 데스크톱 특화 이벤트(`mousedown`, `mouseup` 등)를 사용할 때는 모바일 터치 스크린 동작을 고려하여 포인터 이벤트(`pointerdown`, `pointerup` 등)나 터치 이벤트(`touchstart`, `touchend` 등)를 호환하여 구현해야 합니다.
- 포커스 이동 및 소실(blur/focus) 주기가 모바일 디바이스마다 상이하므로 관련 로직을 작성할 때는 팝업이 닫히거나 무시되지 않도록 주의합니다.
- 모바일 가로/세로 레이아웃 및 뷰포트(viewport), `cursor: pointer` 스타일 지정을 고려하여 UI 클릭(터치) 동작이 정상 반응하도록 설계합니다.

## 2. 한국어 지원 원칙 (Korean Translation Principle)
- 프로젝트 문서(구현 계획서, 결과 보고서, 작업 목록 등) 및 안내 코멘트, UI 텍스트를 작성하거나 수정할 때는 한국어로 작성하거나 다국어일 경우 한국어 번역을 최우선으로 반영합니다.

## 3. DB 없는 내용 자동 생성 금지 (No Auto-creation of Missing DB Records)
- 셋업 동기화나 기타 데이터 연동 시, 데이터베이스(DB)에 사전에 등록되지 않은 마스터 데이터(사업장, 장비 모델, 장비 식별 ID 등)가 입력될 경우 이를 서버 코드 내에서 임의로 자동 INSERT/생성해주면 안 됩니다.
- 누락된 레코드는 자동으로 생성하지 않고, 명시적으로 동기화를 차단하고 실패 처리하거나 오류 응답을 반환하여 사용자가 마스터 데이터를 ADMIN에서 수동으로 명확하게 관리 및 등록할 수 있도록 유도해야 합니다.

## 4. 파트 이상 교체 및 수리시 등록되는 파트 세트화 (코드 수정시 항상고려)
- 파트 이상 교체 및 수리 시 등록되는 파트는 "파트 이상 교체 - [비용처리] 코드명" 형태가 1세트로 인식되게 해줘. 이게 맨날 수정할때마다 꼬이는 현상에 대부분이니까 항상 잘 확인해서 수정해줘
- 추가로 물품 상세를 입력하게되면 "파트 이상 교체 - [비용처리] 코드명 [물품상세]" 형태가 1세트로 되니까 참고해서 수정해줘.
- 특히 다중 부품을 등록, 완료, 완료 취소할 때 "파트 이상 교체 - [비용처리] 코드명" 형태와 "파트 이상 교체 - [비용처리] 코드명 [물품상세]" 형태가 데이터 유실이나 꼬임 없이 동시에 개별 독립된 세트로 완벽하게 공존할 수 있게 하고 서로 꼬이지 않게 해줘.
- 대괄호랑 특수문자가 포함되어있어서 수정할때마다 종종 꼬이는 현상이 발견되는데, 수정할때마다 항상 잘 확인해서 수정해줘.
- 작업 등록이나 작업상세정보에 내용부분에 파트가 추가될때 파트 이상 교체 및 수리 라벨이 안붙도록 해줘.

## 5. 정기 작업 시 물품 명 
- 정기 작업 시 물품은 "[비용처리] 코드명" 형태로 등록되니까 참고해줘.
- 추가로 물품 상세를 입력하게되면 "[비용처리] 코드명 [물품상세]" 형태가 1세트로 되니까 참고해서 수정해줘.
- 정기로 작업 완료시에 파트 이상 교체&수리시와 같은 라벨이 안붙도록 해줘.


## 6. 엄격한 크레딧 절약 지침
1) 사용자가 '@파일명' 태그로 명시적으로 요청하지 않는 한, 전체 워크스페이스를 탐색하거나 프로젝트 단위의 저장소 스캔을 수행하지 마세요.
2) 분석 범위는 오직 프롬프트에 직접 제공된 코드 블록이나 '@' 태그로 지정된 특정 파일로만 엄격히 제한하세요.
3) 추론 루프(Reasoning Loop)를 최소화하세요: 사용자의 승인 없이 자율적으로 터미널 명령어를 실행하거나, 빌드/테스트를 반복하거나, 자율적인 수정 루프를 돌지 마세요. 가장 최선의 1차 해결책을 먼저 제시해야 합니다.
4) 맥락(Context)이 부족하거나 해결책이 모호한 경우, 스스로 파일을 찾아 헤매지 말고 사용자에게 추가 정보를 먼저 요청하세요.
5) 설명은 최대한 간결하게 유지하고, 수정된 코드나 직접적인 답변을 제공하는 데 집중하세요.

## 7. 탭 복원 시 자동 검색 및 재연산 전면 금지 (No Auto-Trigger Search on Restore)
- SORT(검색 및 정렬), OPERATION(가동율 분석), TROUBLE(트러블 이력) 등의 페이지에서 다른 화면을 갔다 돌아올 때, 화면 복원 과정이나 백그라운드 리프레시 도중에 이전 필터 세팅에 맞춰 검색 버튼을 자동으로 트리거하거나 `performSortSearch` / `calculateOperationRate` 연산을 재실행하면 안 됩니다.
- 화면은 `sessionStorage` 에 저장해 둔 마지막 렌더링 결과(HTML/차트)를 그대로 읽어와 0ms로 즉시 보여주기만 해야 하며, 사용자가 직접 '검색 및 정렬' / '조회' 버튼을 마우스로 클릭하기 전에는 어떠한 자동 검색 재연산 동작도 수행되어서는 안 됩니다.

## 8. 고객대응 > 파티클 필터 교체 내용 고정 규칙 (코드 수정시 항상고려)
- 고객대응 대분류 하위의 "파티클 필터 교체" 관련 세부 구분 작업은 완료 및 수정 시 내용 텍스트가 임의 수정되지 않도록 항상 "[유상] Particle Filter" 로 고정 노출되고 수정 불가능(Disabled/ReadOnly)해야 합니다.
- 또한 이 건에 연관된 모든 데이터베이스(LogItem, MaintItem)의 기존 내용들 역시 "[유상] Particle Filter" 및 비용처리 itemCost = "유상" 으로 보정 정합성이 유지되게 해야 합니다.

## 9. 모바일 제안박스/드롭다운 스크롤 시 자동 선택 방지 (Prevent Auto-Selection on Mobile Scroll)
- 모바일 디바이스에서 드롭다운 또는 자동완성 제안박스를 터치 스크롤할 때, 첫 터치 지점의 아이템이 바로 선택(클릭)되어 닫히는 현상을 원천 방지해야 합니다.
- 스크롤 가능성이 있는 리스트 아이템의 선택 이벤트에 단순 `pointerdown`이나 `touchstart`를 사용하지 말고, `touchstart`, `touchmove`, `touchend` 및 `mousedown` 이벤트를 정교하게 제어하십시오. 사용자가 터치 후 화면을 움직여 스크롤하는 상황(터치 이동 거리 6px 초과)에서는 아이템 선택을 건너뛰고, 제자리 탭(Tap) 또는 마우스 클릭 시에만 선택 동작이 정상 처리되도록 구현해야 합니다. (예: `common.js` 내 `renderLogPartOptions`의 `log-select-item` 터치 무브 감지 기법 참고)
